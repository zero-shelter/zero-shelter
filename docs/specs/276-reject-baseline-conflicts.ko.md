# 명세: baseline의 충돌한 결정 거부

영문 정본: [276-reject-baseline-conflicts.md](./276-reject-baseline-conflicts.md)

## Issue와 진행 상태

- Issue: [#276](https://github.com/zero-shelter/zero-shelter/issues/276)
- 대상: baseline 파싱과 직접 판정 호출
- 의존 PR: 별도로 승인된 [#275](https://github.com/zero-shelter/zero-shelter/pull/275)의 [기록 함수 수정](./247-preserve-baseline-decisions.ko.md)
- 관련 PR은 Issue에서 연결하며 진행 상태는 GitHub 메타데이터로 관리합니다.

## 문제

현재 schema의 baseline에 같은 fingerprint를 가진 기록이 둘 있고 결정 메타데이터가
다를 수 있습니다. 판정 전에 중복 기록을 줄이면 기록 순서에 따라 적용할 결정이
달라집니다. 예를 들어 만료된 수용과 유효한 수용의 순서를 바꾸면 Finding의 보고
여부가 달라질 수 있습니다.

## 목표

기록 순서나 현재 Finding의 유무에 관계없이 판정 전에 모순된 결정을 거부합니다.
별도로 승인된 기록 함수 정책과 다른 baseline 호환성 동작은 유지합니다.

## 범위

### 포함

- 현재 schema에서 정확히 같은 fingerprint의 기록을 모아, 중복을 줄이기 전에
  `reason`·`acceptedBy`·`expires`·`recordedAt`을 비교합니다.
- 네 값 중 하나라도 다르면 거부합니다. 값 부재와 제공된 문자열·빈 문자열도
  구분합니다. 파싱 중에는 기존 optional 필드 정규화를 거친 값을 비교하며,
  원본 JSON에 더 엄격한 규칙을 추가하지 않습니다.
- `parseBaseline`과 직접 `applyBaseline`/`judge`를 호출하는 경로 모두 검사합니다.
  호출자가 `Baseline`을 직접 만들어 파싱을 거치지 않아도 같은 검증을 받습니다.
- 현재 Finding이 없어도 baseline 전체를 검사합니다.
- 네 결정 필드가 같은 중복 기록은 package·alias·버전·심각도 등 참고 정보가
  달라도 허용합니다.
- 새 충돌 오류는 fingerprint와 충돌 필드 이름을 표시하며 결정 값 원문은 복사하지 않습니다.

### 명시적 제외

- 서로 다른 fingerprint의 alias 결정, 참고 정보 전체의 중복 제거·정규화,
  alias나 참고 정보 전반의 결정성 보장
- 새 schema·fingerprint·순위·출력 필드·의존성·네트워크 호출과
  [기록 함수 정책](./247-preserve-baseline-decisions.ko.md) 변경
- 충돌 자동 수정, 위험 수용, 원자적 파일 교체, PR 병합과 릴리즈 게시

## 입력과 출력

| 구분 | 계약 |
|---|---|
| 입력 | 기존 baseline JSON 또는 직접 판정에 전달하는 `Baseline` |
| 출력 | 유효한 입력의 baseline·판정 출력 형식 유지. 네 결정 값이 같은 중복은 허용 |
| 오류·종료 코드 | 현재 schema의 결정이 충돌하면 파싱 또는 직접 판정에서 오류를 던짐. CLI는 기존 실패 코드 `2`를 반환하고 stdout에 리포트를 출력하지 않음 |
| 호환성 | 다른 schema의 경고, 기존 필드 정규화·검증과 서로 다른 fingerprint의 alias 일치를 유지. 이전 기록 형식도 현재-schema 충돌 규칙을 만족하면 읽음. hook의 읽기·판정 오류는 기존처럼 조용히 종료 `0` |

충돌한 결정 하나를 조용히 고르는 옵션은 없습니다. 사용자는 기록을 검토해 의도한
위험 결정으로 정리한 뒤 다시 판정하거나 기록합니다. 과거 schema는 기존 경로를
따르며 이번 현재-schema 충돌 규칙을 새로 적용하지 않습니다.

## 구조

- 변경 영역: fingerprint로 기록을 줄이기 전 `src/baseline.ts`의 검증.
  직접 호출도 같은 검증 경계를 거칩니다.
- 예상 파일: 위 모듈, baseline·CLI/hook 집중 테스트, 두 README, 영문 명세와 이 번역본
- 공유 계약: 모순된 현재-schema 결정을 순서에 따라 고르는 대신 입력 오류로 거부
- 충돌 가능성: #275 위에 쌓는 별도 PR이며, 해당 PR의 메타데이터 보존·충돌 처리·
  날짜 보충·버전 보충 정책은 바꾸지 않습니다.

## 보안과 개인정보

- 보호할 정보: 사용자가 작성한 사유·결정자·기록일·만료일과 로컬 baseline 내용
- 경계와 흐름: 기존 로컬 baseline 입력을 파서 또는 직접 API가 받아 검증하고,
  기존 판정 흐름으로 넘깁니다. 새 입출력 대상·보관 정보·네트워크·LLM·텔레메트리는 없습니다.
- 위협: 모순된 중복 기록의 순서로 만료되거나 유효한 수용을 고르는 상황을 엄격한
  값 비교로 거부합니다.
- 오류의 한계: 새 충돌 오류는 필드 이름을 표시하고 결정 값 원문은 복사하지 않습니다.
  fingerprint와 파일 경로는 여전히 임의 입력 문자열이며 기존 오류 동작도 유지하므로,
  모든 정보를 가리는 기능은 아닙니다.
- 실패 방식: 일반 판정은 오류로 중단하며 CLI는 기존 오류 처리로 종료 `2`를 반환합니다.
  리포트·history·baseline 파일 출력을 쓰기 전 중단합니다. 그보다 앞서 스캐너가
  파일을 읽거나 subprocess를 실행하는 것까지 막는다는 뜻은 아닙니다.
- hook 호환성: 기존의 비차단 오류 처리를 유지합니다. baseline 읽기나 판정이
  실패하면 추가 문맥 없이 조용히 종료 `0`을 반환합니다.
- 파일 보장: 새 파일 쓰기나 원자성 보장을 추가하지 않습니다.

## QA 기준

다음은 구현에서 확인할 기대 결과이며, 이미 통과했다는 기록은 아닙니다.

| 상황 | 기대 결과 | 확인 위치 |
|---|---|---|
| 정상 중복 | 네 결정 값이 같으면 다른 참고 정보가 달라도 허용 | baseline 집중 테스트 |
| 충돌 입력 | 각 필드와 부재·제공 값의 차이를 두 순서 모두에서 거부. 파서·직접 API 모두 검사 | baseline 집중 테스트 |
| 빈 입력·이전 형식 | Finding이 없어도 충돌한 현재-schema 입력 거부. 빈 baseline과 모순 없는 이전 형식은 유효하며 다른 schema 동작 유지 | baseline 집중 테스트 |
| 경계·호환성 | 기존 optional 정규화 유지, 서로 다른 fingerprint의 alias와 같은 결정의 중복은 새 검사로 거부하지 않음 | baseline 집중 테스트 |
| CLI와 파일 | 종료 `2`, stdout 없음, 요청한 리포트·history·baseline 파일을 만들거나 변경하지 않음 | `test/cli-baseline-conflicts.test.ts` |
| hook | 읽기·직접 판정 오류에서 조용한 종료 `0`과 문맥 없음 유지 | CLI/hook 집중 테스트 |
| 오류의 정보 노출 | 합성 결정 값 원문이 새 충돌 오류에 없고 fingerprint와 필드 이름으로 충돌 식별 | baseline·CLI 집중 테스트 |
| 기존 동작 | 해당 변경에서 필수 테스트·타입 검사·빌드·패키지 QA·설치 CLI 확인 통과 | 저장소 검증과 PR 근거 |

## 에이전트 참고

fingerprint로 중복을 줄이기 전에 원본 기록을 검사하세요. 날짜 보충이나 문자열
공백 제거를 먼저 하지 말고 네 optional 값을 비교하세요. 파서의 기존 정규화와
과거 schema 동작을 유지하세요. 다른 참고 정보의 차이나 서로 다른 fingerprint의
alias 선택까지 해결했다고 말하지 마세요. 합성 임시 baseline만 사용하고 이 저장소의
위험을 수용으로 기록하지 않습니다.

## 결정 기록

| 결정 | 검토한 대안 | 이유 |
|---|---|---|
| 네 필드 충돌 거부 | 첫·마지막·최신 값 선택 | 입력 순서가 위험 결정을 고르면 안 됨 |
| 파서와 직접 API 검사 | 파서에서만 거부 | 직접 만든 baseline은 파싱 없이 판정에 도달할 수 있음 |
| 현재 schema에 한정 | 모든 schema에 적용 | 다른 schema의 기존 경고와 동작 유지 |
| 같은 결정의 중복 허용 | 중복 전체 거부·모든 참고 필드 비교 | 승인 범위는 결정 충돌이며 참고 정보 전체의 통합이 아님 |
| hook 오류 처리 유지 | hook을 차단하거나 새 경고 출력 | 승인된 읽기 수정은 hook 계약을 바꾸지 않음 |
