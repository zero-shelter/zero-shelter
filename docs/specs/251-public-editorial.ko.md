# 공개 문서와 보고서 표현 개선

정본: [English](./251-public-editorial.md)

- Issue: [#251](https://github.com/zero-shelter/zero-shelter/issues/251)
- 설계 근거: 사용자가 승인한 공개 문서·기록·제품 경험 개선 계획
- 관련 작업: README·제품·로드맵은 [#250](https://github.com/zero-shelter/zero-shelter/pull/250)에서 이어가고, 기여 안내와 제품 표현은 별도 PR로 진행합니다.

## 문제와 목표

공개 문서, 보고서 설명, 프로젝트 기록에 반복적인 강조, 근거 없는 주장, 긴 운영 보고가 남아 있습니다. 일부 한국어 문서는 영어 문장 구조를 따르거나 같은 용어를 영어와 한국어로 섞어 씁니다. 개발자가 이 자료에서 제품의 입력·출력·한계와 기여 절차를 이해할 수 있도록 고칩니다.

영어와 한국어의 공개 접점을 모두 검토합니다. 직접 사용과 AI 연동을 주요 사용법으로 유지합니다. AI 기여를 숨기거나 사람의 검토, 측정 결과, 사용자 경험을 지어내지 않습니다.

## 변경 내용

- 현재 main, 배포 버전, 열린 기록과 닫힌 기록을 포함한 Issue·PR·댓글·리뷰, Discussions, 릴리스, 조직 소개, Wiki, npm 소개, 연결된 미디어를 목록화합니다. 공개 기록은 마지막 페이지까지 조회합니다. 위치·문제·근거·수정안·처리 결과를 기록하고 각 항목을 수정, 검토 후 유지, 권한 또는 배포 대기로 구분합니다.
- README는 제품 설명, 재현 가능한 실행, 직접 사용과 AI 연동, 결과 해석과 한계, 상세 안내 순서로 정리합니다. #250의 파일명 수정은 유지합니다. 현재 기능은 제품 문서에서, 제안은 로드맵에서 다룹니다. 논의 중인 캐치프레이즈를 확정된 결정으로 다루지 않습니다.
- 기여·명세·QA·리뷰·승인·보안·개인정보 요건을 유지합니다. 중복 설명과 템플릿을 정리하고 자동 검사, 에이전트 검토, 사람의 승인을 구분합니다. CONTRIBUTING과 AGENTS에 짧은 작성 기준을 추가합니다.
- 기술 안내, 주석, 테스트 이름, 과거 글을 검토하되 기술 근거, 법률 원문, 생성된 고지, 벤치마크 라벨을 보존합니다. 생성 문구의 정정은 생성기를 수정하고 별도로 검증합니다. 벤치마크 스크립트의 설명과 출력 열 제목, 기존 라벨 양식의 안내 주석은 실제 계산을 설명하도록 고칩니다. 수집 자료·라벨 필드·데이터 행은 유지하고 재생성하지 않습니다.
- CLI 도움말은 첫 실행, 결과 저장, baseline·이력, AI 연동으로 묶습니다. 검사 상태, 새 발견 사항, 가능한 조치, 경고를 구분하며 모든 항목에 실행할 수정 명령이 있는 것처럼 표현하지 않습니다.
- HTML은 스캐너 상태와 경고, 결과 요약, 직접 실행과 AI에 맡기기, 발견 사항, baseline·이력·재현 정보 순서로 구성합니다. 두 사용 경로는 같은 조치 결과를 사용합니다. 중요한 경고는 보이고 점수와 용어 설명은 펼쳐 볼 수 있게 합니다.
- 표, 시스템 글꼴, 오프라인 사용, 복사, 펼치기, 테마 기능을 유지합니다. 프롬프트는 작업·제약·재검증을 설명합니다. baseline 수용과 간접 의존성 강제 버전은 계속 사용자가 결정합니다.

## 인터페이스와 제한

사람이 읽는 문구와 HTML 배치만 바꿉니다. 명령·옵션·종료 코드·JSON과 SARIF 스키마·순위·지문·baseline 수용과 비교·hook 동작은 유지합니다. 런타임 의존성, 텔레메트리, 네트워크 동작, 릴리스 자동화를 추가하지 않습니다. 보호 파일은 기존 운영 규칙에 따른 리뷰를 받습니다.

무관한 리팩터링이나 글의 AI 점수를 검사하는 절차를 추가하지 않습니다. 검사를 통과시키려고 테스트 입력·스냅샷·수집 자료·라벨을 재생성하지 않습니다. 다른 기여자의 작업을 보존하고 #246과 겹치는 동작은 수정 전에 조정합니다.

## 공개 기록과 데이터 처리

외부 기록을 수정하기 전에 원문·식별자·URL을 접근이 제한된 로컬 작업 기록에 보관합니다. 갱신 직전에 원문을 다시 조회하고 달라졌으면 새 내용을 검토합니다. 기술 근거·시간 순서·작성자·리뷰·결정을 보존합니다. 과거 제안과 결과는 당시 내용으로 남기고 사실 정정에는 날짜를 적습니다.

권한을 받은 계정이 작성한 글만 수정합니다. 다른 사람의 글은 검토용 초안으로 준비합니다. 승인 상태·타임스탬프·Git 기록·태그·배포 패키지 파일을 바꾸지 않습니다. 백업이나 편집 진행 댓글을 공개하지 않습니다. npm 소개를 바꾸는 데 배포가 필요하면 다음 정식 릴리스를 기다립니다.

기존 로컬 파일과 허가된 GitHub 접점을 사용하며 제품의 데이터 흐름은 바꾸지 않습니다. 비밀정보나 개인정보를 공개 기록으로 복사하지 않습니다. 없는 접점, 권한 부족, 작성자 검토용 초안, 배포 대기는 반영 완료와 구분합니다.

## 검증과 완료 기준

| 대상 | 필요한 근거 |
|---|---|
| 문서 | `git diff --check`, 변경 링크·설명 확인, 영문·한글 의미 비교, 절차·기여자·과거 근거 보존 |
| 코드·출력 | `npm test`, `npm run typecheck`, `npm run build`; CLI·패키지 변경은 설치 QA, `npm pack --dry-run`, 배포 패키지 기본 동작 검사 |
| 에이전트 안내 | 프롬프트·스킬 등 변경 시 `npm run qa:agent` |
| 검사 상태 | 첫 실행, 새 항목 없음, 수용 항목만 있음, 출처 누락, 검사하지 못함, 수정 버전 없음, 직접·간접 의존성, workspace와 지원 패키지 매니저 |
| HTML | 영어·한국어, 밝은·어두운 테마, 좁은 화면, 긴 이름, 많은 항목, 키보드, 복사 성공·실패, 펼치기, 경고 가시성, 오프라인 사용 |
| 계약 | 같은 입력의 기계 출력·순위·판정·종료 코드 일치 |
| 공개 기록 | 전체 목록과 비공개 원문 보관, 수정 후 내용 확인, 다른 작성자의 초안과 배포 대기 구분 |

마지막으로 조직 소개에서 설치와 보고서까지, 기여 안내에서 Issue와 PR까지, 릴리스에서 과거 논의까지 따라 읽습니다. 모든 목록 항목에 처리 결과가 있어야 합니다. 실제 반영과 검토·배포 대기를 구분합니다. 저장소 검수로 변경을 확인할 수 있지만 모든 방문자가 AI가 쓴 느낌을 받지 않는다는 결론까지 내릴 수는 없습니다.

## 결정 사항

사용자가 승인한 계획에 따라 과거 글도 고치되 근거와 작성자를 보존합니다. 현재 절차, 직접 사용과 AI 연동, 보고서 계약을 유지합니다. 전면적인 브랜드 변경, AI 문체 점수 검사, Git 기록 재작성, 소개글만을 위한 npm 배포는 제외합니다.
