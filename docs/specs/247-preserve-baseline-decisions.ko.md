# 명세: baseline 재기록 시 기존 결정 보존

영문 정본: [247-preserve-baseline-decisions.md](./247-preserve-baseline-decisions.md)

## Issue와 진행 상태

- Issue: [#247](https://github.com/zero-shelter/zero-shelter/issues/247)
- 대상: baseline 기록 함수와 기존 CLI 파일 쓰기 경로
- 관련 PR은 Issue에서 연결합니다. 진행 상태와 담당자는 GitHub 메타데이터로 관리합니다.

## 문제

스캐너가 추가되면 병합된 fingerprint가 달라질 수 있습니다. 공통 alias가 같은
수용 기록을 가리키면 판정 함수는 기존 결정을 이어받지만, 기록 함수는 정확히
같은 fingerprint만 찾았습니다. 이 상태에서 다시 기록하면 사유·결정자·만료일과
원래 기록일을 잃고, 이미 만료된 예외가 만료일 없는 수용 기록으로 바뀔 수 있습니다.

## 목표

alias로 다시 일치하거나 Finding이 나뉘고 합쳐져도 원래 결정을 보존합니다.
이전 결정들이 충돌하면 하나를 임의로 고르지 않고, 기존 baseline 파일을 쓰기
전에 오류를 반환합니다.

## 범위

### 포함

- 같은 fingerprint의 기록들을 줄이기 전에 원본 이전 기록을 모읍니다.
- 정확한 fingerprint 일치는 이전 schema가 다를 때를 포함해 기존 기록 함수의
  동작을 유지합니다.
- alias 후보는 이전 schema가 현재 것과 같고, ecosystem·package가 정확히
  일치하며, 현재 Finding과 alias를 직접 공유할 때만 포함합니다. 과거 기록의
  alias를 따라 다른 기록까지 전이해서 찾지 않습니다.
- 모든 후보의 `reason`·`acceptedBy`·`expires`·`recordedAt`을 엄격하게 비교합니다.
  값 부재와 빈 문자열도 구분합니다. 정확한 fingerprint가 일치해도 다른 alias
  후보와 충돌하면 그 결정을 우선하지 않습니다.
- 후보가 있고 네 값이 모두 같으면 그대로 보존합니다. 기록일이 없는 값끼리도
  먼저 비교한 뒤, 기존처럼 호출자가 전달한 `recordedAt`을 보충합니다. 새 Finding의
  기록 방식은 유지합니다.
- lockfile로 확인한 현재 설치 버전을 우선합니다. 그 정보가 없으면 과거 후보들의
  버전을 합쳐 중복을 제거하고 정렬합니다. 현재와 과거 모두 버전 정보가 없으면
  `versions` 키를 넣지 않습니다. 버전은 참고 정보이며 수용의 일치 범위를 좁히지 않습니다.

### 명시적 제외

- `applyBaseline`, 파서, 일반 `judge`의 일치 조건, schema, fingerprint, 순위,
  스캐너, 의존성 또는 네트워크 동작 변경
- 충돌한 결정의 자동 선택, 만료일 갱신, 실제 프로젝트 위험 수용, 날짜 규칙 변경
- 모든 파일 쓰기의 원자적 교체 보장, PR 병합, 릴리즈 게시

같은 fingerprint에 모순된 기록이 있으면 일반 `judge`의 결과가 입력 순서에 따라
달라지는 문제는 별도로 남습니다. 이 기록 함수 수정으로 그 계약이 해결됐다거나
릴리즈 준비가 끝났다고 판단하지 않습니다.

## 입력과 출력

| 구분 | 계약 |
|---|---|
| 입력 | 기존 `baselineFrom` 인자: 순위가 매겨진 Finding, 선택적인 출처·날짜, 이전 baseline, 설치 버전 |
| 출력 | 기존 schema와 키 배치를 유지하고 일치한 결정 메타데이터와 버전 정보를 보존 |
| 오류·종료 코드 | 결정 필드가 충돌하면 기록 함수에서 오류를 던짐. 기존 CLI 쓰기 오류 경로가 종료 `2`를 반환하고 기록 성공 문구는 출력하지 않음 |
| 호환성 | 정확한 fingerprint 일치, 날짜 보충, 출처 정렬과 새 Finding 기록 방식 유지. 일반 `judge` 동작은 변경하지 않음 |

## 구조

- 변경 영역: `src/baseline.ts`의 이전 결정 선택과 버전 보충
- 예상 변경 파일: 위 모듈, 기존 baseline 쓰기·버전·CLI 입력 테스트, 두 README,
  영문 명세와 이 번역본
- 공유 계약: 서로 다른 이전 결정을 고르거나 버리던 재기록을 명시적인 오류로 거부
- 충돌 가능성: 일반 `judge`나 파서의 후속 변경은 별도로 검토하며 이 수정에 섞지 않음

## 보안과 개인정보

- 보호할 정보: 로컬에서 작성한 사유·결정자·만료일과 설치 버전
- 경계와 흐름: 기존 로컬 스캐너 결과와 baseline을 기록 함수가 읽고, 성공 결과를
  기존 CLI가 지정한 로컬 baseline 경로에 저장합니다. 새 전송 대상이나 보관 정보는 없습니다.
- 오류 출력: Finding의 fingerprint와 충돌 필드를 표시하며 `reason`·`acceptedBy`
  원문은 복사하지 않습니다. fingerprint 자체는 임의 입력 문자열일 수 있어 모든
  개인정보를 가린다는 보장은 아닙니다.
- 네트워크·LLM·텔레메트리: 새 동작 없음
- 실패 방식: 결정 충돌은 `writeFile`에 도달하기 전에 거부합니다. 상위 디렉터리는
  이미 만들어졌을 수 있습니다. 다른 디스크 오류나 중단된 쓰기의 원자성은 보장하지 않습니다.
- 사용자 제어: `--update-baseline`은 계속 명시적으로 요청해야 합니다. 충돌한
  기록을 검토해 의도한 위험 결정으로 정리한 뒤 다시 실행합니다.

## QA 기준

다음은 기존 테스트에서 확인할 기대 결과입니다. 이미 검증을 통과했다는 뜻은 아닙니다.

| 상황 | 기대 결과 | 확인 위치 |
|---|---|---|
| 정상 재일치·분리·병합 | 같은 결정 메타데이터를 보존하고, 만료된 예외는 재기록 후에도 만료 상태 유지 | `test/baseline-write-path.test.ts` |
| 충돌·중복 기록 | 네 필드 중 하나라도 다르면 순서와 관계없이 거부. 정확한 fingerprint 일치로 충돌을 숨기지 않음 | 기존 쓰기·CLI 입력 테스트 |
| 빈 값·이전 형식 | 새 Finding의 기본 동작 유지, 날짜 부재 비교 후 보충, 버전 정보가 없으면 키 생략 | 기존 쓰기·버전 테스트 |
| 경계 | 다른 package·ecosystem과 간접 alias는 연결하지 않음. 다른 schema에서는 alias 후보를 추가하지 않음. 현재 버전 우선, 없으면 과거 버전 합집합 정렬 | 기존 쓰기·버전 테스트 |
| CLI 파일 보존 | 임시 합성 baseline의 바이트가 충돌 전후 같고, 종료 `2`, 기록 성공 문구 없음 | `test/cli-inputs.test.ts` |
| 오류의 정보 노출 | 서로 다른 합성 사유·결정자 값은 오류에 나오지 않고, fingerprint와 충돌 필드가 표시됨 | 기존 쓰기·CLI 입력 테스트 |
| 기존 동작 | 필수 테스트·타입 검사·빌드·패키지 QA와 설치 CLI 확인을 통과하고 fixture·snapshot·의존성·실제 baseline은 변경하지 않음 | 저장소 검증과 PR 근거 |

## 에이전트 참고

충돌을 확인하기 전에 fingerprint로 줄인 후보 목록을 재사용하지 마세요. 만료된
기록도 포함해야 합니다. 이를 먼저 빼면 재기록할 때 만료일을 다시 잃습니다.
`--update-baseline` 요청을 기존 위험 결정을 바꿀 허가로 확대하지 마세요. 테스트는
합성 임시 baseline만 기록하고, 이 저장소의 Finding을 수용으로 기록하지 않습니다.

## 결정 기록

| 결정 | 검토한 대안 | 이유 |
|---|---|---|
| 같은 네 필드 보존 | 정확한 fingerprint만 찾거나 기록일을 갱신 | 스캐너 구성이 원래 결정을 지우거나 갱신해서는 안 됨 |
| 필드 충돌 거부 | 정확한·최신·첫 기록 우선, 만료일 삭제 | 위험 결정의 선택은 사용자 몫 |
| 비교 후 기존 날짜 보충 | 비교 전에 부재 날짜를 채움 | 과거 결정 간 차이를 숨기지 않고 기존 동작 유지 |
| 현재 버전 우선, 없으면 과거 합집합 정렬 | 과거 버전 집합 하나 선택 | 입력 순서에 기대지 않고 확인된 설치 정보 보존 |
| 기록 함수에 한정 | 일반 판정·파서 계약도 함께 변경 | 사용자가 승인한 구체적 범위이며 다른 일치 동작은 별도 결정 필요 |
