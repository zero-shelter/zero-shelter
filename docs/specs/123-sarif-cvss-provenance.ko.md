# 기능 명세: SARIF에 CVSS 출처 보존

정본: [English](./123-sarif-cvss-provenance.md). 이 문서는 연결된 Issue의 설계 기록입니다.

## Issue와 담당자

- Issue: #123
- 대상 계층: SARIF 출력 연동
- 관련 PR: #226

## 문제

SARIF 알림은 zero-shelter의 심각도 이름에서 만든 숫자형 `security_severity`를
노출하지만 취약점 권고문에서 이미 가져온 정확한 CVSS 벡터는 버립니다. 코드 주석도
벡터가 없다고 잘못 설명합니다.

고정된 OSV 수집 자료 4개에는 취약점 보고 항목 453개와 심각도 항목
481개가 있습니다. 모든 심각도 항목에는 CVSS 벡터가 있고 숫자 점수는 없으며,
424개 취약점 보고 항목이 하나 이상의 벡터를 제공합니다.

## 목표

취약점 권고문의 정확한 CVSS 벡터가 있으면 SARIF에 보존하고, 숫자형 심각도 구간은
결정론적 대체값이라고 정확히 설명합니다.

## 범위

### 포함

- `finding.cvssVector`를 SARIF 결과의 `properties.cvssVector`에 그대로 복사
- 출처가 벡터를 주지 않았으면 속성 생략
- 기존 숫자형 심각도 구간 매핑을 대체값으로 유지
- 두 README 언어에 호환성 동작 문서화

### 명시적 제외

- 벡터에서 숫자형 CVSS 점수 계산
- 순위, SARIF 수준, 지문, 알림 식별자 변경
- 스캐너 입력 처리나 발견 사항 형식 변경

## 인터페이스

| 방향 | 계약 |
|---|---|
| 입력 | 입력 처리에서 이미 정규화된 선택적 `RankedFinding.finding.cvssVector` |
| 출력 | 값이 있을 때 SARIF 결과 `properties.cvssVector`의 동일한 문자열 |
| 오류·종료 코드 | 새로운 오류나 종료 코드 변경 없음 |
| 호환성 | 선택적 SARIF 속성 추가; 기존 필드와 대체 심각도 구간 유지 |

## 아키텍처

- 변경 계층: SARIF 표시 경계
- 변경 파일: `src/sarif.ts`, `test/sarif.test.ts`, README 번역, 이 명세
- 공유 계약: 추가되는 SARIF 결과 속성만 변경
- 가능한 충돌: 향후 출처가 숫자형 CVSS를 제공할 때만 기존 대체값을 바꿀지 검토

## 보안과 개인정보

- 보호 또는 민감 데이터: 없음. 벡터는 이미 공개 취약점 권고문에서 옵니다.
- 데이터 흐름과 신뢰 경계: 파싱한 취약점 권고문 발견 사항에서 로컬 SARIF 출력으로 이동
- 로그와 보존: 변경 없음
- 네트워크·LLM·텔레메트리: 없음
- 실패 동작: 값이 없으면 선택적 속성 생략
- 사용자 선택: 기존 `--format sarif` 옵션으로 선택

## QA 완료 기준

| 시나리오 | 기대 결과 | 근거 |
|---|---|---|
| 벡터가 있는 발견 사항 | 출처 벡터를 결과 속성에 그대로 보존 | 고정 OSV 수집 자료를 쓰는 SARIF 단위 테스트 |
| 벡터가 없는 발견 사항 | 속성 생략 | SARIF 단위 테스트 |

| 많은 발견 사항 | 각 결과가 해당 발견 사항의 벡터 사용 | 기존 순서형 결과 생성 매핑 |
| 기존 동작 | 심각도 구간, SARIF 수준, 지문, 점수 불변 | 기존 테스트 모음 |
| 악성 텍스트 | `JSON.stringify`가 값을 JSON 이스케이프 | 기존 직렬화 경계 |

## 에이전트 참고사항

여기서 CVSS 점수를 계산하지 않습니다. 출처 근거를 그대로 보존하고 결정론적
정수 순위 계산은 CVSS 부동소수점 연산과 분리합니다.

## 결정 기록

| 결정 | 고려한 대안 | 이유 |
|---|---|---|
| 벡터를 결과 속성에 추가 | 규칙 속성; 숫자 점수 계산 | 벡터는 발견 사항별로 달라지고 수집 자료에는 출처 숫자 점수가 없음 |
| 심각도 구간 유지 | `security_severity` 제거 | 대체값을 정확히 설명하면서 현재 GitHub 알림 표시와 호환성 유지 |
