# 0.0.11 릴리즈 노트

**배포가 보류된 검토용 후보입니다.** [#247](https://github.com/zero-shelter/zero-shelter/issues/247)을
해결하고 다시 검증하기 전에는 태그를 만들거나 배포하면 안 됩니다. 출처 변경으로
지문이 달라진 수용 내역을 다시 기록하면 기존 만료일과 결정 메타데이터가 사라져
한시적 예외가 연장될 수 있습니다. 테스트와 의존성 검사가 통과해도 이 문제가
해결됐다는 뜻은 아닙니다.

정본: [영어 CHANGELOG의 0.0.11 항목](../../CHANGELOG.md#0011).
검증 범위와 한계는 [배포 후보 QA 기록](../qa/reports/2026-11-03.md)에 있습니다.

## 의존 경로와 스캐너별 기여를 보여줍니다

`zero-shelter why <package>`는 npm lockfile에서 설치된 의존 경로를 설명합니다.
`--input`으로 저장된 스캐너 보고서를 읽을 수 있으며, 보고서가 수정 버전을
제공하면 그 버전을 허용하는 경로의 직접 패키지나 막는 범위를 보여줍니다.
lockfile에 이미 있는 버전만 다루며, registry 조회나 업그레이드를 실행하지
않습니다 ([#140](https://github.com/zero-shelter/zero-shelter/issues/140)).

텍스트·JSON·HTML은 병합한 항목 중 스캐너 하나만 보고한 건수와 여러 스캐너가
함께 보고한 건수를 심각도별로 보여줍니다. 이 수치는 해당 실행의 구성일 뿐,
점수를 바꾸거나 스캐너의 정확도를 입증하지 않습니다
([#142](https://github.com/zero-shelter/zero-shelter/issues/142)).

## 심각도 미표시와 정보 수준을 구분합니다

OSV가 인식할 수 있는 심각도 등급을 주지 않으면 `severityKnown: false`를
전달합니다. 호환성을 위해 JSON의 `severity: "info"`는 유지하지만 심각도
점수는 0점으로 처리합니다. 출처가 명시한 정보 수준의 기존 점수는 유지합니다.
터미널과 HTML에서 미표시 상태를 설명하고, SARIF의 숫자형 심각도를 추측하지
않습니다 ([#137](https://github.com/zero-shelter/zero-shelter/issues/137)).

## 검사 범위와 출처를 더 분명히 알립니다

새 항목이 없는 의존성 검사 결과에는 프로젝트의 컨테이너·워크플로·인프라
파일과 비밀정보를 검사하지 않았다는 안내를 표시합니다. JSON은 같은 사실을
`unscanned`로 전달합니다. 제한된 로컬 메타데이터 확인이며 별도 보안 검사를
추가한 것은 아닙니다 (#246).

SARIF는 제공된 스캐너 버전을 `properties.toolVersions`에 보존합니다 (#244).
JSON의 `missingSources`는 baseline에 기록된 출처가 이번 실행에 참여하지
않았음을 전달합니다 (#245). 보고서는 검토할 항목·가능한 조치·스캐너 상태를
구분하고, baseline 기록이 현재 항목의 수용도 포함한다고 안내합니다 (#253).
README와 benchmark 안내는 고정된 capture의 조치 가능 건수를 설명하며 이를
순위의 정확도로 확대하지 않습니다 (#239). 각 PR 링크는 영어 정본에 있습니다.

## 개발 도구의 기존 버전 범위를 갱신했습니다

잠금 버전은 Vitest 4.1.12, Vite 8.3.5, PostCSS 8.5.32,
source-map-js 1.2.2입니다. 같은 npm audit·osv-scanner 경로를 다시 실행해
기존 9건이 더 이상 보고되지 않음을 확인했으며, 건너뛴 출처는 없었습니다.
강제 override나 런타임 의존성을 추가하지 않았습니다 (#270).
패키지·lockfile·plugin 버전은 0.0.11로 맞췄습니다.

## 호환성과 알려진 한계

judge 종료 코드, 지문 생성 규칙, 가중치 표, baseline 파일 형식은 유지합니다.
심각도가 미표시인 항목의 점수는 위에 설명한 방식으로 처리합니다. JSON 문맥은
추가 필드이며 사람이 읽는 출력 문구는 바뀝니다. `why`는 읽을 수 있는 npm
lockfile이 필요하고 도달 가능성이나 악용 가능성을 판단하지 않습니다.
출처에 없는 데이터는 추측하지 않습니다.

제안된 `scanners` 명령·프로젝트 policy·pnpm 의존 문맥 reader·history 확장은
포함하지 않습니다. 한국어 중복 항목의 영어 suffix(#218)와 `--top`으로 잘린
중복 참조(#198)는 남아 있습니다. `why`가 같은 경로를 반복하는 문제는
[#272](https://github.com/zero-shelter/zero-shelter/issues/272)에 기록했으며, 같은
경로는 한 번만 읽으면 됩니다. 우회 방법과 검증하지 못한 범위는 QA 기록에
남겼습니다.
