# 0.0.10 릴리즈 노트

정본: [영어 CHANGELOG의 0.0.10 항목](../../CHANGELOG.md#0010).
이 문서는 해당 버전만 번역합니다.

## 판정의 근거가 더 잘 보입니다

`history`는 raw 보고 수와 merge 후 건수를 outstanding 옆에 표시합니다.
`accepted`가 baseline 전체 크기가 아니라 이번 실행에 일치한 baseline 항목
수라는 설명도 추가했습니다. 텍스트와 JSON 모두 저장된 건수를 제공합니다 (#232).

SARIF는 advisory가 제공한 CVSS vector를 `properties.cvssVector`에 그대로
보존합니다. 숫자형 `security-severity`는 기존의 대략적인 severity band를
유지하며, vector로 CVSS 점수를 계산하지 않습니다 (#226). HTML의 중복 참조는
같은 화면에 형제 항목이 있으면 advisory 이름을 표시하고, 없으면 지문을
유지합니다 (#211).

## baseline을 기록한 출처를 알려줍니다

`--update-baseline`은 확인 메시지 앞에 건너뛴 scanner 안내를 표시하고,
파일에 기록한 scanner 출처를 알려줍니다. 지원하는 단일 scanner 실행은
계속 성공하지만, scanner가 빠졌다는 사실을 숨긴 채 기록하지 않습니다 (#227).

## 프로젝트의 패키지 매니저에 맞춰 안내합니다

scanner가 직접 의존성 여부를 제공하지 않으면 manifest에 선언된 패키지를
직접 의존성으로 인식합니다. 옛 npm/pnpm 형식과 OSV에도 적용되며, 수정 버전이
함께 제공된 경우 직접 업그레이드 명령을 표시할 수 있습니다 (#195).
yarn 프로젝트에 npm lockfile을 만들라고 안내하지 않습니다 (#201).
HTML은 npm 이외의 환경에서 검증할 수 없는 `clears N` 배지와 그 건수를
약속하는 문단을 모두 숨깁니다 (#229). Agent skill은 리포트의 명령과
매니저별 강제 버전 형식을 사용하며, npm 전용 조치가 다시 들어오는 것을
확인하는 QA도 추가했습니다 (#234).

## 기록과 버전 선택의 경계 조건을 다뤘습니다

- 중단된 history 쓰기로 이후의 모든 기록까지 읽지 못하던 문제를 수정했습니다 (#199).
- `expiress`처럼 알 수 없는 baseline 항목 키를 경고합니다. 향후 형식과의 호환성을 위해 판정은 계속합니다 (#200).
- prerelease끼리의 순서를 비교하고, JavaScript의 안전한 정수 범위를 넘는 숫자 식별자도 처리합니다. 버전의 `v` 접두사도 인식합니다 (#170).
- osv-scanner에 검사할 패키지 출처가 없는 경우를 scanner 실패와 구분합니다 (#190).

## 기여와 설치 검증을 개선했습니다

기여 가이드와 PR template에 fork CI의 maintainer 승인 대기를 설명했습니다
(#220). CI 예제의 osv-scanner 다운로드는 버전을 고정하고 checksum을
검증합니다 (#221). 설치 QA의 subprocess와 CI job에 시간 제한을 두고,
CLI 제한은 scanner 제한보다 길게 잡았습니다. 판정하지 못한 이유도 실패한
검사에 표시합니다 (#160). README에 첫 기여 이슈를 찾는 경로를 추가했고
(#164), CODEOWNERS와 branch protection을 통해 Owner 리뷰 요청과 승인·필수
검사를 연결했습니다 (#202).

## 호환성과 알려진 한계

기존 judge 종료 코드, 지문 생성 규칙, ranking 가중치, baseline 수용 의미는
바뀌지 않습니다. history JSON 건수와 선택적 SARIF vector는 추가 필드이며,
사람이 읽는 출력 문구는 바뀝니다. 항목이 사라져도 반드시 고쳐졌다는 뜻은
아니므로 계속 **더 이상 보고되지 않음**이라고 표현합니다.
패키지·lockfile·plugin 버전은 0.0.10으로 일치합니다 (#203).

옛 pnpm/npm 6 리포트에서 실행 가능한 수정 버전을 전달하지 못하는 경우는
#204와 아직 머지되지 않은 #233에서 다룹니다. 한국어 HTML의 중복 항목에
영어 `fixed in` 문구가 남는 문제는 #218에 있습니다. 새 scanner나 제안된
`scanners` 명령(#163)은 이번 릴리즈에 포함되지 않습니다.
